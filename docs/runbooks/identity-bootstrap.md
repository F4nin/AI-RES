# Runbook: первый администратор и секреты идентичности (S07)

**Статус:** процедура проверена на локальном стеке (профиль `bootstrap` проходит статическую проверку Compose; интерактивный запуск контейнера — вручную, см. ниже). Production-проверки и ротация секретов — вне S07 (G-78). Нормативная основа: Authentication and Session Management v1.1 §3.3; Secrets and Key Management v1.1.

## Что создаёт `make secrets-dev`
- `mfa_encryption_key` — base64 от 32 случайных байт; ключ AES-256-GCM для seed TOTP. Монтируется только в `api`.
- `bootstrap_secret` — одноразовый секрет первого администратора. Монтируется только в сервис `bootstrap`; в `api` его нет (проверяется `check_compose.py` и runtime-тестом).
- Пароль БД `ai_res_api` теперь монтируется и в `api`, и в `bootstrap` (роль без DDL и BYPASSRLS).

## Создание первого администратора (один раз на установку)
1. `make up` (стек и миграции `0012`–`0013` применены).
2. `make bootstrap ORG="Название организации" EMAIL=admin@example.com NAME="Имя Фамилия"`.
3. На запросы ввести: содержимое `infra/secrets/runtime/bootstrap_secret` (ввод не отображается), затем пароль (≥ 15 символов, не из denylist) дважды.
4. Результат: напечатаны только `organization_id` и `user_id`. Укажите `organization_id` в `AI_RES_DEFAULT_ORGANIZATION_ID` (если установка одноорганизационная) — иначе логин требует `organizationId`.
5. Повторный запуск отказывает (`already_bootstrapped`, код выхода 2): одноразовость хранится в `platform.bootstrap_state`, а не в файле секрета.

Коды выхода: `0` создан · `2` отказ (неверный секрет, слабый пароль, повтор, несовпадение паролей) · `1` ошибка конфигурации/подключения.

## Сразу после
- Войти в UI/через API и включить TOTP (`POST /auth/mfa/enrollment` → `…/confirm`); сохранить recovery codes (показываются один раз). Привилегированные действия `iam.*` без подтверждённого второго фактора запрещены Policy Engine.
- Удалить `bootstrap_secret` из рабочего окружения оператора, если он не нужен (ограничение: файл остаётся в `infra/secrets/runtime` до следующего `make secrets-dev`/`reset`).

## Чего здесь нет (открытые пункты)
- Ротация `mfa_encryption_key` (id ключа хранится в blob; процедура перешифрования не написана), `bootstrap_secret`, кольца идемпотентности, ключей сервисов — SEC-027, G-78, G-80.
- Восстановление доступа, если потеряны и пароль, и MFA, — через привилегированный сброс MFA другим администратором (`MfaService.reset`, аудируется); путь без второго администратора не реализован (G-82).
