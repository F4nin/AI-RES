# S16 — план минимальных реальных проверок и смета

**Дата проверки источников:** 2026-11-17. **Статус:** подготовлен для рассмотрения перед платными вызовами; **НЕ ИСПОЛНЕН**. Текущий provider расход агента 0 USD; общий оставшийся лимит S16 10 USD. Этот план не утверждает модель/Bifrost и не разрешает исключение из immutable baseline.

## Предпосылки

1. Решение NCP-16: доказанный immutable selector или явно согласованная новая нормативная семантика. API alias `deepseek-flash` сейчас соответствует опубликованной версии `DeepSeek-V4.1-Flash-1017`, но это не закрепление. Provider ID — DeepSeek; Pro не участвует.
2. Provider key находится в защищённом host-side store и монтируется только relay; значение не передаётся чату, argv, env, Runtime или отчётам. Сейчас такого key mount в overlay нет.
3. Проверенная isolated PoC composition, auth/egress, точный допуск без production approval bypass, протокол учёта всего расхода S16 и прекращения до исчерпания. Не использовать неизвестные прежние списания как нулевые. Перед началом повторно сверить тарифы/идентификаторы/limits.

## Минимальный набор

| Попытка | Реальная проверка | Ограничение |
|---|---|---|
| 1 | Небольшой structured JSON результат и локальная schema validation | Synthetic public input, без project content и секретов |
| 2 | Генерация одного function tool call | Только генерация/validation аргументов; инструмент и внешнее действие не исполняются |
| 3 | Короткий завершённый stream, конечный usage | Проверка fragment/finish/identity и закрытия соединения |
| 4 | Отмена stream и cleanup | Неизвестный расход считается полностью возможным до reconciliation |

Максимум **4 HTTP attempts всего**, включая любой повтор: автоматические retries/fallback выключены на обоих слоях; повтор заменяет одну из ещё не исполненных проверок, не добавляется сверх четырёх. `max_tokens` провайдера ≤1024 (не-thinking), запрос text-only; body ≤65,536 bytes, одно выполнение одновременно. Временные ограничения WORKING: 30 s на запрос, отмена в четвёртом тесте после первого chunk. Бюджет не является целевым расходом; не делать лишних вызовов. Error/429/unavailable/secret/SSRF/cross-scope ветки сначала локально, без подмены реальной совместимости этими тестами.

## Оценка

[Официальные тарифы](https://api-docs.deepseek.com/quick_start/pricing/) на дату проверки: Flash peak cache-miss input **0.30 USD / 1M tokens**, output **1.20 USD / 1M tokens**. Discount/cache-hit/off-peak в верхней оценке не учитываются. [Models API](https://api-docs.deepseek.com/api/list-models/) документирует context window 1,048,576 tokens. Поиск/URL/file/server tools отключены и не должны порождать отдельные списания.

Реальный ожидаемый usage до тестов неизвестен. Иллюстративный расчётный сценарий 512 input +256 output на каждую из четырёх попыток даёт **0.0018432 USD**; это предположение для оценки порядка стоимости, не измеренная величина и не обещание.

Для консервативной границы не полагаемся на WORKING оценку input по bytes: считаем на каждую попытку полное опубликованное context window как вход и ещё 1024 output. `4 × (1,048,576 × 0.30 +1,024 × 1.20) /1,000,000 = 1.2632064 USD`. Это заведомо завышает размер разрешённого payload. Граница условна соблюдением провайдером опубликованных token caps/тарифов, отсутствием скрытых retries/дополнительных server tools; это отдельные условия реальной проверки, не гарантия текущего локального ledger. При невозможности подтвердить их — запрос не отправлять.

## Учёт и остановка

До dispatch резервировать максимальную цену оставшейся попытки в общем журнале S16; отсутствие/неоднозначность usage, timeout, cancel или ошибка после dispatch оставляют полный резерв израсходованным до сверки. Не считать отсутствие ответа отсутствием списания. Если консервативная цена следующей попытки не помещается в фактический остаток 10 USD с предыдущими/неизвестными списаниями — остановиться. Процессный in-memory ledger и input estimate сами по себе не обеспечивают общий лимит между restart/retry прогонами; протокол должен это компенсировать до live test.

После каждого вызова записать только безопасные metadata: request ref/время, model identity по согласованной семантике, input/output/usage, attempts, cancellation/outcome, стоимость по dated тарифам, отдельно provider billing и расхождения. Никаких prompts, raw responses или ключей. Итог: фактическое число вызовов, расходы, неопределённые суммы и остаток S16; качество продукта/месячный расход из четырёх технических проб не выводить.
