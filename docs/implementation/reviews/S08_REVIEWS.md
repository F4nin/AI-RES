# S08 — независимое review (слой 3 ADR-037)

**Дата:** 2026-11-12 · **Состав:** `security-reviewer`, `code-reviewer`, `silent-failure-hunter` (blind-first: отчёт автора и ADR агентам не передавались; read-only, код не менялся). Основание запуска: правило `ecc-precedence.md`, п. 2 — этап вводит новую матрицу политик, разрешение проекта в обход прямого RLS-контекста и меняет поведение отказов Policy Engine (граница безопасности).

Итог: **CRITICAL — 0; HIGH — 1 (исправлено)**; MEDIUM/LOW исправлены или зарегистрированы (ниже). Повторный проход агентами по дельте исправлений не проводился (проверено тестами, см. отчёт §9).

## Находки и их судьба

| # | Источник | Сев. | Суть | Судьба |
|---|---|---|---|---|
| 1 | code | HIGH | ETag `"3"` несовместим с `parse_if_match` (`"v<N>"`) → вечный 412 при записи (S09) | **Исправлено**: `format_etag`; тест фиксирует `"v1"`→`"v2"` |
| 2 | code, security, silent | MED | Перебор проектов в GET по id: O(P) транзакций на промах, DoS | **Смягчено**: предел `read_lookup_max_projects` (WORKING) → 503 с логом; полное решение — G-87 |
| 3 | security, silent | MED | Вложенные соединения (UoW → движок → аудит отказа) → истощение пула, 503 | **Исправлено**: `PolicyEnforcer.decide` до открытия транзакции данных + `record_allow`; тест 60 параллельных запросов |
| 4 | silent | MED | `run_list` превращал любые `ValueError/TypeError/KeyError` в 400 «Invalid cursor» (маскировал баги) и откатывал аудит ALLOW | **Исправлено**: форма keyset проверяется до транзакции; широкий `except` удалён; тест «плохой курсор не создаёт строк аудита» |

| 8 | code, security | MED | `GET /projects` не вызывает движок (SQL-зеркало) | **Принято как исключение** (ADR-075) + параметризованный тест равенства SQL и движка |
| 9 | code | MED | Тесты не покрывали ничьи по времени, limit == размер, числовые keyset, просроченные/испорченные курсоры, формат ошибки limit | **Исправлено**: добавлены тесты |
