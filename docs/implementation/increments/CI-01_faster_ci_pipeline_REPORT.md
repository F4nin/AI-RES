## Шаг 0 — профиль (выполнен 2026-11-14)
Метод: временный плагин pytest (вне репозитория) с прямыми таймерами фаз и фикстур (hookwrapper `runtest_setup/call/teardown`, `fixture_setup`, промежутки между тестами). Выборка: `test_read_api.py`, `test_policy_engine.py`, `test_iam_login.py` — 331 DB-тест, локально (8 ядер, Docker Desktop), 418,2 с.

| Что | Время |
|---|---|
| сбор тестов / старт | 0,5 с / 0,7 с |
| setup | 381,0 с (91%) |
| call | 35,2 с (8%) |
| teardown | 0,8 с |
| промежутки между тестами | 0,02 с |
| фикстура `migrated` (alembic upgrade head на каждый тест) | 309,1 с (0,94 с/тест, 74%) |
| фикстура `empty_db` (DROP DATABASE + provision ролей/прав) | 47,4 с (0,14 с/тест, 11%) |
| `pg` (старт контейнера, один раз) | 1,7 с |

Вывод: основная потеря — повторная миграция схемы с нуля на каждый тест. Ранний замер через `--durations` давал неполную сумму (157 из 364 с) из-за моего неполного учёта; прямые таймеры сходятся с окном прогона. Оценка для полного набора (≈ 900 с из 977 с) — прикидка, подтвердит шаг 4.

### Перепроверка шага 0 (второй независимый прогон, другие файлы)
Выборка 2: `test_write_api.py`, `test_repositories.py`, `test_tenant_context.py`, `test_s06_repositories.py` — 88 тестов, 111,7 с. Добавлен независимый прямой замер вызова `alembic.command.upgrade` (не через учёт фикстур).

| | Выборка 1 (331 тест) | Выборка 2 (88 тестов) |
|---|---|---|
| окно прогона | 417,4 с | 111,1 с |
| setup / call | 91% / 8% | 86% / 14% |
| `migrated` | 309,1 с = 74% (0,94 с/тест) | 78,1 с = 70% (0,90 с/тест) |
| прямой замер `alembic upgrade` | — | 87 вызовов, 78,09 с (совпадает с фикстурой 78,1 с) |
| `empty_db` | 47,4 с = 11% (0,14 с/тест) | 12,2 с = 11% (0,14 с/тест) |
| промежутки между тестами | 0,02 с | 0,0 с |

Итого по 419 тестам: `migrated` 387 с из 528 с = 73%. В миграциях сейчас 17 ревизий (`backend/src/ai_res/db/migrations/versions`); время `upgrade head` растёт с каждым этапом.

Оценка для полного набора (прикидка): 819 PostgreSQL-тестов × 1,07 с (migrated + empty_db) ≈ 877 с из 977,7 с локального прогона. Это экстраполяция с двух выборок на 51% PostgreSQL-тестов (419 из 819); тесты `test_migrations*` и аналогичные намеренно мигрируют сами, и часть тестов не использует `migrated`. Подтвердит шаг 4.

Оговорки: профилируемый прогон выборки 1 шёл 418 с против 364 с без плагина (разброс ≈ 15%, вероятно нагрузка машины/накладные расходы плагина); доли фаз в двух прогонах совпадают, абсолютные секунды колеблются.
