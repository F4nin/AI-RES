## Шаг 2 — кеши и тяжёлые шаги (в работе)
Разбор времени `infra-runtime` по логу run `43482169301` (11,4 мин):

| Фаза | Время | Примечание |
|---|---|---|
| `make up`: пуллы третьих образов | ≈ 19 с | параллельно, быстро |
| `make up`: сборка 4 собственных образов | ≈ 147 с | из них ≈ 120 с компиляция MinIO и mc из исходников (`go build`) |
| `make up`: запуск и health | ≈ 21 с | |
| runtime-тесты | 166 с | |
| SBOM + скан | ≈ 296 с | на третьи образы ≈ 264 с; на каждый третий образ Trivy запускался **дважды** (счётчик + отчёт) |

Выполнено **2a**: скан третьих образов — один запуск Trivy на образ, счётчик читается из того же JSON-отчёта (`infra/scripts/supply_chain.sh`). Отчёт и счётчик те же, отказ при пустом/битом отчёте сохранён (проверено на синтетических отчётах: валидный → 2; пустой, битый, отсутствующий → exit 1 и обрыв под `set -e`). `shellcheck` и `bash -n` проходят. Полный прогон скрипта локально не выполнялся (нужен собранный стек из 14 образов): эффект (≈ −100…130 с) — оценка, подтверждается CI.

Отложено и обосновано:
- **Вынос SBOM/скана в отдельный джоб (2c):** собственные образы пришлось бы собирать заново, а `backend` (13,7 мин) после шага 1 остаётся критическим путём; вынос окупится только после шагов 4–5, когда `backend` станет короче `infra-runtime`.
- **Кеш БД Trivy:** отвергнут — устаревшая БД ослабляет доказательство скана; выигрыш не измерен.
- **Кеш слоёв образов, прежде всего MinIO (2b, ≈ 120 с):** кандидат; требует buildx cache и, вероятно, стороннего action (закрепление по SHA) — решение отдельным ADR после 2a.
- **Кеш `uv` и таймауты/`--durations` в CI (2d):** мелкие, выигрыш < 20 с; делаются вместе.
