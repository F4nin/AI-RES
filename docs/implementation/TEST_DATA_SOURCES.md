# TEST_DATA_SOURCES — источники данных для тестирования качества Workers

**Статус документа:** рабочий, ненормативный. Перечень открытый: пополняется по ходу работы (владелец, 2026-11-14).
**Важно:** названия и описания ниже — из знаний Implementation Lead, **не проверены**. Лицензия, актуальность и условия использования каждого набора проверяются **до** загрузки данных в репозиторий или в запросы к модели (колонка «Проверено»).

Назначение: сквозной экспериментальный прогон (SLICE-01, ADR-115), затем оценочные наборы S33 (elicitation, extraction, conflict detection, decomposition, artifact generation, recovery).

## Правила использования
- Проектные данные владельца (обычные, без коммерческой тайны и персональных данных) допустимы для egress в DeepSeek (OD-01, 2026-11-14); третьи наборы — только после проверки лицензии.
- Крупные наборы и документы с неясной лицензией в git не коммитятся; в репозитории хранятся ссылка, версия/дата загрузки, SHA-256 и скрипт получения.
- Синтетические данные (в том числе сгенерированные моделью) помечаются как синтетические и не выдаются за реальные.
- Веб-исследование источников — общими запросами; код, документы и идентификаторы AI RES во внешние сервисы не отправлять (ecc-precedence).
- Эталоны (gold) фиксируются вместе с версией набора; изменение эталона — новая версия, старая не мутируется.

## Приём «бесплатного эталона»
Взять SRS с пронумерованными требованиями, превратить документ в обычный текст без нумерации, прогнать Requirements Worker и сравнить результат с исходным списком: **полнота** (сколько исходных требований найдено) и **точность** (сколько придумано лишнего).

## Детерминированные проверки результата (не зависят от суждения модели)
- ответ проходит схему WorkerResult (S14);
- у каждого требования есть ссылка-доказательство, а цитата реально присутствует в источнике (проверка на выдумки);
- тип требования входит в реестр, неизвестный получает UNKNOWN;
- в ответе нет секретов;
- adversarial: «инструкция» внутри документа (prompt injection) не исполняется.
