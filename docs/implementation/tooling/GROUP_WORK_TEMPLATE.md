# Шаблон паспорта группы

Применяется после поручения на группу по [DEVELOPMENT_GROUPS.md](../DEVELOPMENT_GROUPS.md), ADR-124/127. Создать `docs/implementation/groups/Gxx_WORK.md` в рабочей ветке выбранной группы; каталог создаётся при первом запуске. Это не замена промптов и отчётов Sxx. До поручения паспорта активных групп не создавать.

## Идентификация и полномочия

- Группа, общий проверяемый результат, дата.
- Точное поручение владельца; разрешённые этапы, scope и исключения.
- Исполнитель; координатор, если есть другие активные окна.
- Статус группы: NOT_STARTED / IN_PROGRESS / BLOCKED / DONE.
- Git worktree, ветка группы, проверенная база/HEAD/diff; чужие изменения.

## План и зависимости

| Этап | Промпт / отчёт | Внешние DONE / внутренние контракты | Owner/security блокеры | Статус реализации / готовности | Общий PR / SHA / покрытие CI |
|---|---|---|---|---|---|

Указать порядок исполнения, точки ожидания других групп, уже DONE этапы и условия проверки общего результата. Внешние зависимости требуют DONE перед соответствующим зависимым Sxx; внутренние реализовать в порядке DAG в одной ветке до общей приёмки. READY не означает новое разрешение, DONE группы не заменяет human approval.

## Владение файлами и средой

- Разрешённые пути; общие файлы и договорённость с координатором.
- Контракты/API wiring, миграции/head, ADR-номера, manifests/locks, Makefile/CI.
- Владение runtime: окружение, текущий checkout/SHA/diff, данные/миграции, окно использования, запрет конкурирующих команд.
- Совместимость объединённой ветки/миграций и безопасная общая проверка без удаления существующих данных.
- Уже разрешённые egress/расходы; что требует отдельного решения.

## Gates и выполнение

Фазы группы: реализация всех Sxx → общая отладка → независимое review/исправления → финальные проверки/доставка. Отдельные полный pre-pr, CI, review и PR/merge после каждого внутреннего этапа не требуются. Полезные точечные проверки разрешены; тесты/миграции/observability/отчёты готовятся вместе с кодом.

Для каждого Sxx указать применимые G1–G9, специальные gates и нужные ECC-компетенции. Общие suites и read-only blind-first reviewers могут покрыть несколько этапов с явной картой покрытия. Один полный pre-pr и обязательный Linux CI по итоговому SHA группы, включая дополнительные security jobs, сохраняются. После исправлений повторить затронутые проверки; автор не проверяет себя независимо.

До общей приёмки этапы имеют IN_PROGRESS/IMPLEMENTED. После проверки записать для каждого stage report ссылки на общий review/PR/CI, SHA, среду, команды/exit codes/counts/skips и оставшиеся gaps. TESTED/VERIFIED/DONE должны соответствовать evidence именно этого scope. Общие документы вести без потери записей соседней группы.

## Продолжение и остановка

- Текущий этап и точная оставшаяся работа.
- Следующий этап внутри группы; проверенные зависимости, что ещё ожидается.
- Блокер, влияние, evidence и необходимое решение/внешний результат.
- Где сохранён контекст для новой сессии.
- При DONE — проверка общего результата, ссылки на evidence всех этапов, оставшиеся ограничения продукта; остановка перед другой группой.
