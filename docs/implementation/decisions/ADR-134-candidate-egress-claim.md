# ADR-134 — Candidate PoC: backend claim непосредственно у egress

**Дата:**2026-11-17. **Статус:** ACCEPTED technical implementation scope по продолжающемуся поручению на подготовку; runtime/security acceptance NOT VERIFIED. G02/S17/S20/S21 не начинаются. Источники: DOC076v1.1§3.1/5/7, IAM/Auth service identity, ADR128/133, read-only egress analysis в G02_FLASH_ADMISSION§6.

Выбран A: relay проверяет фактически полученное после Bifrost тело по versioned codec, формирует canonical окончательные bytes и делает private-TLS backend claim фиксированного technical account. Только identity LLM_GATEWAY с audience API и узкой candidate capability. Backend связывает digest с заранее reserved immutable case, повторно проверяет plan/tariff/account и коммитит onceclaim+audit до positive reply. Relay отправляет ровно эти bytes через content=. Статический relay Bearer/allowbool без claim не разрешает egress.

Новая отдельная candidate ASGI app не монтируется в public/internal product app. Операции только claim и settlement; нет HTTP reserve/account creation/profile approve/budget extension. Caller не выбирает account/plan/grants. Отсутствие HTTPS, неправильный issuer/audience/capability, отсутствующий reserved case, unknown codec/hash, closed/blocked account, storage/audit/HTTP failure запрещают dispatch. Нет retries/redirects/cookies/proxy environment. Relay не получает DB credentials.

Canonical body codec0.1 принимает только заранее определённые короткие synthetic templates TEXT/JSON/TOOL/SSE/CANCEL/TIMEOUT с уникальным random synthetic marker внутри body каждой попытки. Формат и все влияющие на выполнение поля контролируются; marker не несёт project/user/source данных. Body≤4096UTF8bytes, output cap256, non-thinking, concurrency1. Permanent UNIQUE bodyhash в ledger исключает повтор старого запроса против новой reservation. Recheck использует новую marker/body и тот же общий8attempt limit, не automatic retry.

Settlement читает usage непосредственно из проверенного provider response у relay, до преобразования Bifrost; caller/model не задаёт rates/charge. Unknown/cancel/timeout сохраняют полный резерв. При rollback/store failure claim остаётся pending; при commit-success и lost HTTP ACK backend уже может быть SETTLED. Relay не считает исход подтверждённым и не повторяет dispatch; DB остаётся истиной, exact settlement replay не дублирует charge. успешный transport без accounting не объявляется принятым evidence. Неизвестная identity/fingerprint не auto-approval; candidate facts остаются evidence, не продуктовым результатом.

Используются existing Ed25519 service tokens без изменения ar1, private CA/hostname verification и отдельная host composition. Tariff freshness/точные permissions и human model approval не выводятся из service identity. Пока concrete host/key/freshness wiring не проверены, actual provider calls disabled; tests включают только synthetic fixtures/fake upstream. Новых реальных accounts/tariffs/profiles/approval seeds и ключей этот шаг не создаёт. Product factory/immutable ModelProfile/BifrostTransport остаются прежними.

План реализации: pure codec/tests + backend control service/ASGI/tests; затем relay private TLS client/claim+settlement/failure handling; bounded development runner/evidence collector; настоящие private-TLS/PG/replay/restart/pinned-Bifrost→fake-upstream tests и независимые general/security reviews. Никаких DB migration изменений в первом control срезе; applied0020–24 immutable. Нужда в новой persistence field/contract фиксируется отдельно до изменения.

Альтернатива B — offline signed permit/boot nonce/replay cache — отклонена для текущего PoC из-за нового crypto wire/mint/revocation semantics. A не закрывает ADR129/OD19/G107 продуктового Runtime и не выдаёт permissions Manager/Worker. После реального допуска сохраняются SLICE01 и новое согласие на G02.
