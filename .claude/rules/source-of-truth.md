## Обязательные действия перед существенной задачей

Перед изменением кода, созданием миграции, изменением контракта или архитектурного решения:

1. Открой `AI_RES_Document_Registry_v4.1.md` §2 и найди актуальный canonical path для затронутой области.
2. Убедись, что файл физически существует в `docs/architecture/`.
3. Прочитай актуальную версию — не полагайся на кешированное знание о содержимом.
4. Если файл отсутствует: **остановись**, выпусти discrepancy report, не используй старую версию как fallback.
5. Если две нормативные версии противоречат: **не выбирай молча**. Зафикисруй конфликт с ссылками на документы и разделы — решение принимает владелец проекта.

## Статусы документов и что они означают

| Статус | Что означает | Что НЕ означает |
|---|---|---|
| `BASELINED` | Утверждённый нормативный дизайн/требования | Наличие кода, PoC, runtime, security/performance acceptance |
| `WORKING` | Параметр в работе, не финализирован | Запрет использовать — но нельзя молча изобретать значение |
| `PROPOSED` | Предложение, не подтверждённое владельцем | Разрешение реализовывать |
| `DECIDED` | Решение подтверждено владельцем | Полную реализацию (детали могут быть WORKING) |
| `SUPERSEDED` | Заменён более новой версией | Любую нормативную силу |
| `REFERENCE` | Исходный методический материал | Нормативные требования AI RES |

Частичный BASELINED явно перечисляет WORKING-параметры и post-MVP ограничения. Нельзя молча расширять частичный baseline на WORKING части.

## Правила версионирования нормативных документов

- Для каждого логического документа существует **одна** актуальная версия в реестре.
- Новая версия создаётся после проверки актуального файла, связанных документов и реестра.
- Изменение архитектурного решения отражается **во всех затронутых документах** в рамках одного изменения.
- Реестр обновляется в том же изменении, что и документы.
- Предыдущие версии сохраняются как история; нормативная сила только у версии из реестра.

## Доменная истина при реализации

| Данные | Canonical source |
|---|---|
| Project/Epic/Task/Requirement/Artifact state | PostgreSQL `ai_res_db` |
| Temporal execution state и история Workflow | Temporal (`temporal_db`) |
| LangGraph reasoning state | LangGraph checkpoints (изолированная schema) |
| Бинарное содержимое источников и артефактов | MinIO |
| Operational Operation state | PostgreSQL `operations` schema |
| Иммутабельные ReadinessEvaluation | PostgreSQL `execution` schema |

Temporal **не заменяет** PostgreSQL как источник истины для доменных объектов. Worker не является источником истины для результатов — только WorkerResult в PostgreSQL.
