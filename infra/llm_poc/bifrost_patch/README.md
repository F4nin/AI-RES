# Candidate-only Bifrost metadata patch

Base: official `maximhq/bifrost` commit `7cb75fb2f8276ca48d0792c857fecb67b8879e2f` (v2.5.1). Apply `fingerprint.patch` only to a separate verified source copy. Dependency manifests, official image, S16 configuration and main Compose remain unchanged. Local candidate build/provenance belongs to the separate build tooling.

The guard applies only to DeepSeek / `deepseek-flash` native chat streaming (no integration context and no Responses fallback). It checks actual raw `id`, `model`, and fingerprint presence/value before decode, forwarding or suppression. Identity values must be nonempty strings. Fingerprint ABSENT, NULL and VALUE remain distinct. Changed/missing/duplicate/invalid metadata or malformed frames terminate safely without fallback; rejected upstream connections use the existing no-drain abandon path. Each forwarded/terminal chunk owns its checked fact. No missing value is filled from a previous frame.

Native stream serialization verifies the retained tuple before overlaying its observed fingerprint on the existing `WithPreservedUsage` output. Exact-path converters and post-hooks must retain the original checked fact and matching base fields; dropping, replacing or mutating them stops the request. The guarded input/output must be exclusively the chat variant; injecting another response family is refused both at the hook boundary and before native serializer dispatch. Hooks cannot rewrite an integrity refusal into success or a skipped chunk. Legacy string fields and explicit-zero usage remain intact. Error messages contain no raw metadata. This does not approve a profile, enable provider calls or establish real-provider evidence.

Tests included in the patch cover raw parsing/presence, JSON/sonic serialization, legacy/zero usage, request-local isolation, exact scope, and actual Go handler streams with hidden finish/usage drift, A→B→A, malformed/duplicate/type errors, hook/converter mutation, safe refusal, no repeated request and upstream abandonment. These Go tests make no real inference calls. The separate patched-image/fake-upstream compatibility suite is mandatory under ADR135; real-provider acceptance remains a later gate.

For behavioral RED, add only `core/providers/openai/chat_stream_metadata_test.go` to the unchanged verified source copy and run `TestFlashNativeStream*`. For GREEN apply the whole patch. Use the approved pinned builder, `GOTOOLCHAIN=local`, task-owned caches, `GOMAXPROCS=2` and `go test -p 2`; include race and vet for `./schemas` and `./providers/openai`. Never alter upstream module/lock files or auto-install a toolchain. Local `gofmt` is syntax/format evidence only, not a Go test result. Runtime results are recorded separately after execution and independent review.
